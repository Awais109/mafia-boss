# The app

The React Native layer: `App.tsx` and `app/`. It renders state and dispatches actions; all game rules live in the engine ([architecture.md](architecture.md)). Built with Expo SDK 57 and no navigation library ([ADR 0008](decisions/0008-app-shell-and-ui.md)). It is dressed in the warm-ledger design ([ADR 0047](decisions/0047-warm-ledger-design.md)): bundled fonts, SVG glyphs and icons, a bottom bar with More.

**Status:** typechecks, lints, and bundles for Android (`npx expo export --platform android`). It has not been launched on a device or simulator in development so far. A web export is used only to screenshot screens against the design ([below](#checking-screens-against-the-design)). `/start-android` and `/start-ios` run it in Expo Go; `/install-android` and `/install-ios` install a standalone build ([native-builds.md](native-builds.md)).

## Entry and shell

- `index.ts` registers `App`.
- `App.tsx` wraps everything in `SafeAreaProvider`, calls `store.start()` once, loads the fonts (`useFonts(FONT_ASSETS)`), and renders a loading spinner until the first snapshot exists and the fonts have loaded or failed. Then the `Cover` until Continue ([ADR 0049](decisions/0049-scenes.md)); then `Header`, `TutorialBanner`, `NoticeBar`, the active screen, the bottom bar, and one overlay at a time: `AwayModal` while a "while you were away" summary is pending, else `SceneViewer` while a scene is playing ([ADR 0049](decisions/0049-scenes.md)), else `EventNoticeModal` while a live notice is queued ([ADR 0038](decisions/0038-live-event-notices.md)), and `SkipSheet` when the header's gold chip is tapped.
- **The bottom bar** (`BAR` in `App.tsx`) holds five tabs: Home, Business (tab id `rackets`), Fronts, Ops, and Map (tab id `turf`). The active one is brass with a brass rule above it.
- **More,** the sixth slot, opens `MoreSheet`, a bottom sheet listing the rest (`MORE`): Crew, Heat, Stats, How it works (tab id `help`), Log, and Debug (only when `debug.enabled`). Each row carries a one-line status (`moreNote`): crew used and idle, heat and the line it's over, the game day. While one of these is open, More is the active slot.
- A dot on a tab means it wants attention: Home when a decision is waiting, Tolya has a demand, or an alert is up (vault full, running costs Dirty can't cover, cigarettes running out or out, an offer about to expire; `homeNeedsAttention` in `app/inbox.ts`), Fronts when there's Dirty and buffer room, Ops when crew are idle, Heat at or above `heat.inspectThreshold` (`badges` in `App.tsx`). More shows a dot when anything inside it has one, and the sheet repeats the dot on that row.
- Screens receive `{ game, go }` (`app/screens/types.ts`): the current snapshot, and a function to switch tabs (it also closes More).
- On web only, `?tab=<id>` in the URL opens on that tab (`initialTab`), for the screenshot rig.

## The store

`app/store.ts` exports the `store` singleton and a `useGame()` hook (`useSyncExternalStore`).

**Lifecycle**
- `start()`: loads settings and the save, begins a session, starts a 1 s tick, and listens to `AppState`. Coming to the foreground begins a session; going to the background ends it.
- A save that fails `migrate` is copied to `sevgorod-save-unreadable-<timestamp>.json` and a new game starts, with an error notice.
- Game time is `Date.now() + state.debugOffsetMs + state.skippedMs` (hours bought with gold).

**Actions and ticks**
- `dispatch(action)`: tick first (so a gap becomes an away summary and `apply` only sees the action), then `apply` at game time, append an `action` line to the log, write the save, append any events. A rejected action shows its error in the notice bar. After a time-offset action it ticks immediately. A successful `SKIP_TIME` builds its own away summary from the states before and after, titled "Skipped N hours"; any other action with events queues live notices instead (`buildNotices`, `app/notices.ts`).
- The 1 s `tick`: reconciles to now. A gap long enough to count as being away builds/merges an away summary; otherwise any events queue live notices the same way. If anything happened (events), or the gap counted as being away, it commits and persists. Otherwise it only refreshes the displayed snapshot, so nothing is written while idle.
- `Snapshot` = `{ state, derived, config, settings, configErrors, now, realNow, notice, away, notices, scene }`.
- **Scenes** ([ADR 0049](decisions/0049-scenes.md)): each refresh, if no scene is playing, the store latches the one due (`dueScene` in `app/scenes.ts`) and keeps it until `endScene(id)`, which records it (`SEE_SCENE`) and lets the next due one in. `playScene(id)` plays one by hand (Debug's Preview; dossiers later).

**Sessions:** `SESSION_START` and `SESSION_END` (with real duration and action count) are dispatched as actions, so they're in both the save stats and the log.

**Config:** `setPreset`, `setOverride(path, value | null)`, `resetOverrides(prefix?)`, `presetConfig()`. Each change writes settings, appends a `config` log line, and puts a `CONFIG_CHANGED` event in the game log. An invalid config never bricks the game: the store falls back to plain defaults and Debug shows the errors.

**Data:**
- `resetGame()` starts over with a fresh log.
- `importSave(json)` validates with `migrate` and writes a new `meta` line.
- `exportSave()` and `exportLog()` share a JSON file via `expo-sharing`. Sharing isn't available on web.
- `runBot(days)` plays the save with the sim's casual bot (`sim/driver.ts`), appends the bot's actions to the log, and moves `debugOffsetMs` forward by the days played. The notice names any act reached or cleared during the run.

## While you were away

([ADR 0023](decisions/0023-away-summary.md)) When a tick finds the save 15 game minutes or more behind now (`AWAY_MIN_GAME_MINUTES` in `app/store.ts`, the shortest job), it builds an `AwaySummary` from the catch-up reconcile and `AwayModal` shows it until dismissed. That happens on launch, on returning from the background, after a Debug time skip, and after importing an old save; the Bot commits its own end state, so it doesn't trigger one. On the `fast` preset the threshold is 15 real seconds.

`app/away.ts` is pure: `buildAway(before, after, events, config, to)` and `mergeAway(pending, next)`, which extends a summary that hasn't been dismissed when another gap arrives. The summary holds:

| Field | From |
|---|---|
| `jobs` | `OP_RESOLVED` events: job name, crew (named from the state at the gap's start), outcome, Dirty, Influence, Rep |
| `racketsEarned`, `lostToCap`, `vaultFull` | `stats.dirtyEarned` delta minus job rewards; `stats.dirtyLostToCap` delta; the vault against its cap |
| `fronts` | Each front's buffer delta (nothing is deposited offline) and the Clean it made at the front's rate |
| `cleanEarned`, `tributeLost`, `seized`, `influenceEarned` | Stats and state deltas |
| `wagesPaid`, `wagesShort` | `WAGES_PAID` and `WAGES_MISSED` events |
| `upkeepPaid`, `upkeepShort` | `UPKEEP_PAID` and `UPKEEP_MISSED` events |
| `packsMade`, `packsSold`, `packsLost`, `stockFrom`, `stockTo` | Stats deltas and the stock before and after |
| `goldGranted`, `skippedHours` | `GOLD_GRANTED` events; set by the store for a skip |
| `heatFrom`, `heatTo` | Heat before and after |
| `pendingDecisions` | `after.inbox.length`; the popup points the player to Home |
| `events` | Everything else except bookkeeping; the modal runs them through `describeEvent` and drops quiet lines |

The summary is not saved: closing the app loses it, and the Log still has every event.

## Storage

`app/storage.ts`: `read`, `write`, `append`, `remove`, `uri`, using the `File`/`Paths` API from `expo-file-system` in the app's document directory. Web falls back to `localStorage`.

| File | Contents |
|---|---|
| `sevgorod-save.json` | The `PlayerState` |
| `sevgorod-settings.json` | `{ preset, overrides }` |
| `sevgorod-log.jsonl` | One JSON line per entry: `meta` (game start snapshot and config), `action`, `config`, `event`. Format in `sim/replay.ts` |
| `sevgorod-export-save.json`, `sevgorod-export-log.json` | Written just before sharing |

## Components and helpers

- `app/theme.ts`: the palette (`colors`: ground, shell, card, nested card, hairline, divider, control; bone, muted and faint text; brass accent and attention dot; warn, good, and red as text; the eight resource colours), the notebook's `paper` inks, and `fonts`, the loaded family names by role (`display700`–`900`, `text400`–`600`, `speech`, `caption`, `hand500`/`hand700`); `textFont(weight)` picks the text face for a weight.
- `app/fonts.ts`: `FONT_ASSETS`, the ten font files keyed by those family names, imported per weight from `@expo-google-fonts/*`.
- `app/components/Glyph.tsx`: `Glyph({ kind, size, color })`, the eight resource glyphs drawn in SVG on a 12-unit square; `Icon({ name, size, color })`, the line icons (the bar and More destinations, close, chevrons, check, lock, warning, blocked, and the Act V–VI marks); `GLYPH_CHAR` and `CHAR_RESOURCE` map resources to their text glyphs and back.
- `app/components/ui.tsx`: the primitives (`List` and `Item`, a card of rows edge to edge under hairlines with an optional mark on the left; `Check`, a checklist box: todo, done or now; `Meter`, the boxed bar under a big figure; `BigFigure`; `Tile`, a nested box with a caps label; `Pill`, a small state label; `AlertRow`; `Strip`, a tinted warning inside a card; `Empty`, a dashed box where something will be; `BuyRow`, something to buy with its price and what it does, or a dashed row saying why not; `Segmented`, a row of exclusive choices in a sunken track; `SectionLink`; `PageHead`, a More screen's title in the display face; `SubHead`, a caps heading inside a list; `Note`, a section rule's right note; `Screen`, `Section` with a brass caps title and a hairline rule, `Card` with brass, warn and alert tones, `Row` with a hint under the label, `Totals`, `T`, `Title` in the display face, `Btn` in primary brass, normal, danger and ghost with an optional second line, `BtnRow`, `Bar` with threshold marks, `Tag` (plain for a kind, tinted when it says something), `Money`, `Divider`), and `rich(text, size, { mono, plain })`, which turns each text glyph in a string into a drawn `Glyph` and colours the figure after it in that resource's colour (Heat figures in red); `plain` leaves the figures in the text's colour (a cost), `mono` draws every glyph in one colour (a brass button's label), `ink` draws them in their paper inks (`paperInk` in `app/theme.ts`) for the notebook. `Btn` also has an `outline` kind and a `chevron` for buttons that go somewhere. ## Look and feel

The warm-ledger design ([ADR 0047](decisions/0047-warm-ledger-design.md)) comes from Claude Design. It has three registers:
- **Data screens** are a printed ledger: warm dark cards, brass section titles over a hairline rule, condensed type, and figures in their resource's colour.
- **Story scenes** are grown-up crime manga (not built yet).
- **The map** is Lyosha's notebook (not redrawn yet).

The design lives in `design/` as an input:
- `sevgorod-design-brief.md` is the brief Claude Design was given: the world, the cast, and every screen with its states.
- `Sevgorod Screens.html` is what came back: every frame, the component sheet and the identity page.

Don't edit either; record a deviation in an ADR.

## Checking screens against the design

A web build renders the same components, so screens can be screenshot at phone width and set beside the frames in `design/Sevgorod Screens.html`:

1. `npx expo export --platform web --output-dir <dir>`, then serve `<dir>` (for example `python3 -m http.server`).
2. To show a save, write its JSON to `localStorage['sevgorod-save.json']` before the page loads. A sim state from `simulate(...)` (`sim/driver.ts`) passed through `shiftTimes(state, Date.now() - state.updatedAt)` opens without an away summary.
3. Open `/?tab=<id>` to start on a tab; on the Map, `&view=people` opens People and `&person=<id>` a dossier (`PersonId` in `app/art/people.ts`). `&sheet=skip` or `&sheet=more` opens a sheet, and `&preview=<name>` a notice or a scene (`PREVIEWS` in `app/previews.ts`). Any `tab` parameter starts past the cover; a URL with none shows it. A save shifted so its clock is eight hours behind opens with the away summary. Headless Chrome won't make a window narrower than about 500 px, so put the page in a 390 px-wide iframe to get a phone's width.

Sharing and the file system fall back or no-op on web ([Storage](#storage)); nothing else about the build is supported for play.
